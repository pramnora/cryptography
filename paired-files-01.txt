VERSION 1

So, we have a file...which contains a random list of either: letters/words.

Then, we have a separate but related file...which stores a list of numbers.

Now, both of these files are actually inter-related with one another...;
in that the 'numbers' file selects the exact 'letters/words' in their correct order.

EXAMPLE: random letters...
FILE A: adgasfaOSDFGASSFAGBOAKDJSAO[]ADFA]
FILE B: 1,6
...so the selected letters are: 
1=a
6=f

EXAMPLE: random words...
FILE A: JAGGED OPEN closed WHEN ADDICT CLEAR
FILE B: 3,2
...so the selected words are:
3=closed 
2=OPEN

So, in this scenario...an interceptor might find the file of random letters/words;
or, alternatively, they might find the file of numbers...;
but, without finding both files...; 
they wouldn't know what is related to what...?

VERSION 2

Instead of just 2 files,
one could have any number of files say: 0-99=100 different files;
...so, first, we would generate 100 files: having numbers: 00-99/
...and, each of these files containing a mixture of random letters.

The numbers file will point to which: fileNo/letterPos

Now, if we wish to encode the string: This
...we would store each letter inside the string...into a different fileNo/filePos;
...so,,. 
T, file number: 00/rndPos: 10
h, file number: 30/rndPos: 42
i, file number: 50/rndPos: 64
s, file number: 92/rndPos: 99
...so, the numbers file might look like this:
0010304250649299
...where the first 2 digits do indicate: which file
...where the next 2 digits do indicate: which rndPos in that file
...so, now, the interceptor has to find...not just 2 files/but, multiple;
...and, what if each of these files was stored inside of different places. 

We could also change letters into numbers...This = 20080919...(including numbers up to 00-99).
And, the numbers file itself could be mixed in with one of these files going from 00-99.
